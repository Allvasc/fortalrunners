Variáveis de ambiente

Toda variável que o backend lê. Cada uma diz o que faz, se é obrigatória, como obter e onde configurar no Render. O arquivo prático para copiar é backend/.env.example.

Como ler as etiquetas: obrigatória a API não sobe sem ela · só em prod tem default de dev, mas em produção precisa de valor real · opcional vazia = o recurso degrada com elegância (501 / sandbox / fallback).

01 Núcleo

Sem isto a API não funciona. Em produção, gere segredos fortes e nunca os commite.

DATABASE_URLobrigatória

String de conexão do PostgreSQL + PostGIS. A API roda as migrações no boot (a menos que AUTO_MIGRATE=false).

Exemplo postgres://user:senha@host:5432/fortalrunners?sslmode=require

Render injetado automaticamente pelo banco fortalrunners-db (fromDatabase no render.yaml).

Precisa de extensões postgis, pg_trgm, citext (o Postgres do Render tem todas).

JWT_SECRETsó em prod

Assina os tokens de acesso, o token curto de 2FA e o QR rotativo do atleta. Em produção precisa de ≥ 32 bytes — a API recusa subir com menos.

Gerar openssl rand -base64 48

Dev usa um default inseguro se vazio.

Render já está no render.yaml (troque por um valor gerado).

MFA_ENC_KEYsó em prod

Chave AES-256-GCM que cifra em repouso: o segredo TOTP do 2FA, os tokens de integração (Strava) e os telefones de contato de emergência. base64 de exatamente 32 bytes.

Gerar openssl rand -base64 32

Dev usa um default fixo se vazio ou inválido.

Render já está no render.yaml (o valor atual decodifica para 32 bytes — troque por um gerado).

CORS_ORIGINSopcional

Lista (separada por vírgula) de origens permitidas no CORS. Também define para onde o callback OAuth redireciona (a 1ª origem) e a base do link público de beacon (/s/:token).

Default http://localhost:5173

Prod https://fortalrunners-web.onrender.com (ou seu domínio).

APP_ENVopcional

dev · staging · prod. Em prod a API exige JWT_SECRET forte e MFA_ENC_KEY válida.

Default dev · Render já setado como prod.

HTTP_ADDR · PORTopcional

Porta de escuta. O Render injeta PORT e ele sobrepõe HTTP_ADDR — não setar PORT à mão.

Dev HTTP_ADDR=:8090 (a 8080 costuma estar reservada no Windows).

REDIS_URL · NATS_URL · LOG_LEVEL · ACCESS_TOKEN_TTL · REFRESH_TOKEN_TTLopcional

REDIS_URL — cache/sessão (ainda pouco usado; default redis://localhost:6379/0).

NATS_URL — fila. Sem NATS a API processa território + rollup no próprio processo (é o caso do deploy atual).

LOG_LEVEL — debug|info|warn|error (default info).

ACCESS_TOKEN_TTL / REFRESH_TOKEN_TTL — duração dos tokens (default 15m / 720h).

02 Login social

Opcional. Vazio → GET /v1/auth/oauth/:provider responde 501 e a UI mostra "não configurado".

GOOGLE_CLIENT_ID · GOOGLE_CLIENT_SECRET · GOOGLE_REDIRECT_URLopcional

Credenciais OAuth 2.0 do Google Cloud Console → "Credentials" → "OAuth client ID" → tipo "Web application".

Redirect a cadastrar no Google <API>/v1/auth/oauth/google/callback — e o mesmo valor em GOOGLE_REDIRECT_URL.

Prod https://fortalrunners-api.onrender.com/v1/auth/oauth/google/callback

APPLE_CLIENT_ID · APPLE_TEAM_ID · APPLE_KEY_ID · APPLE_P8_KEY · APPLE_REDIRECT_URLopcional

Do Apple Developer (precisa de conta paga). Crie um Services ID (é o APPLE_CLIENT_ID, ex.: com.allvasc.fortalrunners.web) e uma Sign in with Apple key (.p8).

APPLE_TEAM_ID 10 caracteres, canto superior direito da conta.

APPLE_KEY_ID id da chave .p8.

APPLE_P8_KEY o conteúdo inteiro do arquivo .p8, incluindo -----BEGIN PRIVATE KEY----- / END. No Render, cole tudo no campo de valor (quebras de linha são aceitas).

Redirect <API>/v1/auth/oauth/apple/callback (Apple exige HTTPS — não funciona em localhost).

03 Strava

Opcional. Import de atividades + webhook de novas corridas. Vazio → /v1/integrations/strava/* responde 501.

STRAVA_CLIENT_ID · STRAVA_CLIENT_SECRET · STRAVA_REDIRECT_URL · STRAVA_WEBHOOK_VERIFY_TOKENopcional

Crie um app em strava.com/settings/api. O "Authorization Callback Domain" deve ser o host da API (sem https://).

STRAVA_REDIRECT_URL <API>/v1/integrations/strava/callback

STRAVA_WEBHOOK_VERIFY_TOKEN uma string que você inventa; precisa bater com o valor usado ao registrar o webhook (hub.verify_token).

Termos exibir "Powered by Strava" e link "Ver no Strava"; dados só do próprio usuário.

04 Pagamentos — Asaas

Opcional. Vazio → modo sandbox: o checkout cria o pedido e devolve um PIX marcado como demo (não é um BR Code válido, ninguém paga). Com a chave, entra o fluxo real.

ASAAS_API_KEYopcional

Chave da API do Asaas (Configurações → Integrações → API). Use a chave de sandbox primeiro (asaas-sandbox.com).

Sem ela checkout funciona em modo demo (útil para desenvolver o fluxo de inscrição sem cobrar).

ASAAS_WEBHOOK_SECRETopcional

Segredo para verificar a assinatura HMAC-SHA256 do webhook em POST /v1/webhooks/asaas. O webhook é sempre idempotente (por webhook_events); a verificação de assinatura só acontece quando este segredo está setado.

Produção obrigatório na prática — sem ele qualquer POST no webhook seria aceito.

Onde defina o mesmo valor no cadastro do webhook no painel do Asaas.

05 Coach IA

Opcional. Vazio → o coach responde com um fallback determinístico (dicas fixas por palavra-chave), sem chamar LLM. A telemetria e os guardrails funcionam nos dois modos.

ANTHROPIC_API_KEY · AI_MODELopcional

Chave da Anthropic Console. Com ela, POST /v1/coach/ask monta o contexto só com dados do próprio usuário e chama o modelo, com limite por usuário (15/h) + teto global diário e timeout de 20 s.

AI_MODEL default claude-sonnet-5.

06 Clima

WEATHER_API_KEYopcional

Chave do OpenWeather (plano gratuito, API clássica 2.5). Com ela, GET /v1/conditions devolve a leitura real de Fortaleza (temperatura, sensação, UV, vento, janelas boas). Sem ela, cai numa leitura estática marcada como tal — a mesma interface Provider, com fallback automático se a chamada real falhar.

07 Map-matching, e-mail & erros

Três integrações opcionais. Cada uma é no-op sem a variável — o app funciona igual, só sem aquele reforço.

OSRM_URLopcional

Base de um servidor OSRM com perfil a pé (ex.: https://osrm.seu-dominio.com, sem barra final). Ao registrar a corrida, o traçado limpo é encaixado na malha viária (/match) antes de virar geometria — o território passa a seguir os quarteirões reais. points_jsonb continua com o GPS cru; métricas e anti-fraude não mudam. Falha de rede ou baixa confiança → segue com o traçado cru, sem erro. Vazio = desligado (comportamento atual).

RESEND_API_KEY · EMAIL_FROMopcional

Chave da Resend (plano gratuito cobre o MVP) para o e-mail de redefinição de senha. EMAIL_FROM é o remetente verificado, ex.: FortalRunners <nao-responda@seu-dominio> (default: onboarding@resend.dev). Sem a chave, o link de redefinição só aparece no log do servidor.

SENTRY_DSNopcional

DSN do projeto no Sentry (plano gratuito). Com ele, todo erro 5xx e todo panic vão para o Sentry com tags de rota, método e request-id. RENDER_GIT_COMMIT (injetada pelo Render) marca a release. Vazio = SDK em modo noop.

08 Operação

AUTO_MIGRATEopcional

false desliga a migração automática no boot da API (útil quando um job de migração roda à parte). Qualquer outro valor = liga.

TARGETbuild arg

Não é env de runtime — é um ARG do Dockerfile (api | worker | scheduler | migrate) que escolhe qual binário compilar. O render.yaml passa TARGET=api.

09 Front — web & mobile

VITE_API_URLbuild-time (web)

URL completa da API (com https://). Lida no build do Vite. No render.yaml está https://fortalrunners-api.onrender.com.

apiUrl (mobile — app.json → expo.extra)config

Não é env var: é o campo extra.apiUrl em mobile/app.json. Hoje http://localhost:8090; troque para a URL de produção antes de gerar um build (EAS).

10 O que já está no render.yaml

Estas o Blueprint já injeta — você só precisa trocar os segredos por valores gerados e adicionar as opcionais que quiser ativar (login social, Strava, Asaas, IA) nas Environment do serviço fortalrunners-api no painel do Render.

Automáticas DATABASE_URL, REDIS_URL, PORT

Fixas no blueprint APP_ENV=prod, JWT_SECRET, MFA_ENC_KEY, CORS_ORIGINS, ASAAS_WEBHOOK_SECRET (adicionar), demais opcionais

Você adiciona quando ativar: GOOGLE_*, APPLE_*, STRAVA_*, ASAAS_API_KEY, ANTHROPIC_API_KEY, WEATHER_API_KEY, OSRM_URL, RESEND_API_KEY, EMAIL_FROM, SENTRY_DSN (todas já declaradas com sync:false no blueprint)

Checklist mínimo para produção de verdade: gerar JWT_SECRET e MFA_ENC_KEY novos · setar ASAAS_WEBHOOK_SECRET antes de habilitar pagamento real · nunca commitar o .env.
